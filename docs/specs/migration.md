# Spec: Migration behaviour

## Execution order (`migrator.run_job`)

1. **Introspect** the selected databases and tables, then **plan**. Plan warnings are logged.
2. **Schemas:** `DROP SCHEMA … CASCADE` if `drop_existing` is set, then `CREATE SCHEMA IF NOT EXISTS`. Any failure here aborts the job.
3. **Tables:** `CREATE TABLE` with columns, identity, defaults, `NOT NULL` and enum `CHECK`. There are no keys at this point. If a table already exists, that table fails with a hint to enable `drop_existing`.
4. **Data** (when `include_data` is set): for each table, an unbuffered MySQL select → `fetchmany(batch_size)` → converters → `COPY FROM STDIN`, in one PG transaction per table. Progress is published at most every 250 ms.
5. **Post steps**, per table that loaded successfully: primary key, indexes, identity `setval`, ON UPDATE triggers, comments.
6. **Foreign keys**, after every table in every selected database has loaded, so cross-database references work.
7. **Views:** rounds are retried until no further view succeeds, which resolves dependencies between views. Views that are left over are logged as warnings.
8. **Verify** (`verify_row_counts` together with `include_data`): `COUNT(*)` on both sides. A mismatch is a warning.

Error isolation: a failure in steps 3–8 affects only that table or step. A table that fails in step 3 or 4 is excluded from the later steps.

## Naming

- The target schema is `target_schema`, or the MySQL database name passed through `pg_ident`.
- `pg_ident(name)` lowercases the name when `lowercase_identifiers` is set. Otherwise it keeps the name exactly, quoted.
- Derived names use `short_name(...)` (63 bytes max, md5 suffix if truncated):
  - PK `<table>_pkey`
  - index `<table>_<index>`
  - trigger `<table>_<col>_on_update`
  - function `trg_<table>_<col>_on_update`
- FK constraint names keep the MySQL name, which is unique per table in PG.

## Type mapping (`typemap.map_type`)

| MySQL | PG | Notes |
|---|---|---|
| tinyint(1) | boolean | only if `tinyint1_as_boolean` is set and the column is not auto_increment |
| tinyint / smallint | smallint | smallint unsigned → integer |
| mediumint | integer | |
| int | integer | int unsigned → bigint |
| bigint (any sign) | bigint | **must stay bigint so FKs stay compatible** |
| decimal(p,s) | numeric(p,s) | |
| float / double | real / double precision | |
| bit(1) / bit(n) | boolean / bit(n) | |
| char(n) / varchar(n) | char(n) / varchar(n) | lengths are in characters on both sides |
| *text, enum, set | text | enum adds `CHECK (col IN (values…, ''))` |
| json | jsonb | does not occur on 5.6, kept for forward compatibility |
| binary, varbinary, *blob | bytea | |
| date / datetime(f) / timestamp(f) / time(f) | date / timestamp(f) / timestamptz(f) / time(f) | |
| year | smallint | |
| spatial | text | selected as `ST_AsText(col)` (WKT) |
| anything else | text | |

`AUTO_INCREMENT` on smallint, integer or bigint becomes `GENERATED BY DEFAULT AS IDENTITY` (BY DEFAULT, so COPY can insert the explicit ids).

**Invariant:** if column A has a FK to column B, `map_type(A)` must equal `map_type(B)` whenever MySQL's own FK rules allow the pair. Any new integer rule must keep auto_increment and non-auto_increment columns of the same MySQL type on the same PG type.

## Defaults (`typemap.map_default`)

- No default, or auto_increment → no default.
- Temporal `CURRENT_TIMESTAMP…` → `CURRENT_TIMESTAMP`. A zero-date default is dropped with a warning.
- Boolean targets → `true`/`false`, parsed from `1`/`0` or `b'1'`.
- bit(n) → `B'…'`, zero-padded to n.
- Numeric → passed through only if it matches a numeric literal. Otherwise it is dropped with a warning.
- Binary or spatial → dropped (except `''` → `''::bytea`).
- Everything else → a quoted string literal via `ql()` (NUL bytes stripped).

`ON UPDATE CURRENT_TIMESTAMP` becomes a plpgsql `BEFORE UPDATE` trigger per column.

## Value conversion (per row, during COPY)

| Source | Rule |
|---|---|
| boolean targets | `v != 0`; `bytes` → `any(v)` |
| bit(n) | bytes → big-endian int → `'0101'` string padded to n |
| date / datetime / timestamp returned as `str` (invalid or zero date) | `NULL` if the column is nullable, else `'-infinity'` |
| time (`timedelta`) | becomes `datetime.time` if within 0 to 24h. Otherwise **raise**, which fails that table with a clear message. Never clamp. |
| text-like | strip `\x00`; `bytes` → utf-8 decode with replacement; `set` → comma-joined |

Rule: converters must either keep the value or fail loudly. They must never silently change valid data.

## Indexes

- PRIMARY → `ALTER TABLE … ADD CONSTRAINT … PRIMARY KEY` (always created, even when `create_indexes` is off).
- UNIQUE / regular BTREE/HASH → `CREATE [UNIQUE] INDEX`.
- Prefix parts `col(n)`:
  - unique → expression `left(col,n)` (`substring` for binary), which keeps uniqueness semantics.
  - non-unique → full-column index first, with the prefix expression as `fallback_sql`.
- FULLTEXT → `GIN (to_tsvector('simple', coalesce(a,'') || ' ' || …))`.
- SPATIAL → skipped with a warning.

## Foreign keys

Created only when the referenced table is part of this migration. Otherwise they are skipped with a warning. Unknown referential rules fall back to `NO ACTION`.

## Views

`translate_view_sql` rewrites only the following. Anything else is left to fail and be reported:
- backtick identifiers → double-quoted (database names mapped to target schemas, other names through `pg_ident`)
- `IFNULL(` → `coalesce(`
- `CURDATE()` → `current_date`
- charset introducers `_utf8mb4'…'` → `'…'`

## Out of scope (reported, not migrated)

Stored routines and triggers (counted and reported as warnings), events, users, grants, partitions, and table options such as engine and charset.
